# FreeRADIUS sidecar

This directory holds the opinionated FreeRADIUS 3.2 configuration used by
the `--profile eap` Docker Compose stack. It is intentionally minimal — just
enough to terminate EAP-PEAP / EAP-TLS / EAP-TTLS and proxy the inner identity
verification to NACo via the `/api/v1/eap/*` REST hooks.

## Layout

```
raddb/
  clients.conf                # NAS shared secrets (placeholder default-network)
  mods-available/rest         # rlm_rest pointing at NACO_EAP_URL
  sites-available/default     # outer auth + accounting → rlm_rest
certs/                        # generated by `bootstrap` on first run
```

## First-time setup

1. Generate a private CA + server cert. FreeRADIUS ships a `bootstrap` script
   in its `certs/` directory — invoke it once before launching the stack:

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.eap.yml \
     run --rm freeradius /etc/raddb/certs/bootstrap
   ```

2. Set the shared bearer token in `.env`:

   ```
   NACO_EAP_BEARER_TOKEN=<long-random-string>
   ```

   …and make sure `eap.enabled: true` + `eap.bearer_token: "$NACO_EAP_BEARER_TOKEN"`
   in `/etc/naco/config.yaml`.

3. Set per-NAS shared secrets in `clients.conf` (and the RADIUS secret in
   NACo for the same NAS — they're independent).

## Production hardening

* Replace `default-network` with per-NAS `client { ... }` blocks bound to
  specific IPs.
* Replace the auto-generated CA with one issued by your PKI.
* Increase `require_message_authenticator = yes` enforcement to all clients
  (it's already on by default in `clients.conf`).
* Restrict the `rlm_rest` URL to a private network or service-mesh endpoint.
