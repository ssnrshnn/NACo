# NACo runtime dependencies.

# Version policy: a lower bound (>=) pins the minimum tested release; an upper
# bound (<) guards against a breaking *major* being pulled in unattended — an
# AAA server should never silently adopt a new major of FastAPI, SQLAlchemy,
# Pydantic, etc. Security-critical libraries (cryptography, pillow) are left
# without an upper bound so patch/minor security fixes flow in automatically.
#
# For byte-for-byte reproducible production images, generate a fully pinned,
# hash-locked file *inside the target runtime* (matching the Dockerfile base
# Python), e.g.:
#     pip install pip-tools
#     pip-compile --generate-hashes -o requirements.lock requirements.txt
# and have deploy/Dockerfile install from requirements.lock.
